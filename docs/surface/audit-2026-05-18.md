## Findings

### CLI Contract Is Human-Readable, Not Agent-Native

The CLI is simple and non-interactive, which is good, but agents cannot reliably parse its output or discover its schema.

| Severity | File | Issue | Dimension |
| --- | --- | --- | --- |
| High | `src/cli.js:9` | Help is plain text only; no `--json` or `--schema` command discovery. | CLI Design |
| High | `src/cli.js:26` | `init` mutates files but has no `--dry-run` or `--print` mode. | CLI Design |
| Medium | `src/cli.js:49` | `explain` returns prose rather than structured allow/block data. | Tool Design |
| Medium | `src/check.js:18` | Check errors are line-oriented text only, hard to classify programmatically. | Error Handling |

Suggested approach: add shared output helpers with `--json`, `--schema`, and `--dry-run` across all commands before adding more features.

Dependencies: none.

### Error Handling Needs Stable Machine Codes

Current errors are useful for humans but weak for automated recovery.

| Severity | File | Issue | Dimension |
| --- | --- | --- | --- |
| High | `src/cli.js:109` | Top-level catch emits `boundaries: ${message}` with generic exit code 1. | Error Handling |
| Medium | `src/check.js:63` | Missing Turbo produces a human hint but no code such as `TURBO_NOT_FOUND`. | Error Handling |
| Medium | `src/check.js:41` | Config validation errors do not include stable codes, affected file paths, or recovery hints as fields. | Error Handling |

Suggested approach: define a `BoundaryProblem` shape with `code`, `message`, `is_retriable`, `suggestions`, and optional `file`.

Dependencies: CLI JSON output.

### Agent Context Is Bundled But Not Root-Discoverable

The package ships a useful skill, but agents entering the repository do not get root-level guidance.

| Severity | File | Issue | Dimension |
| --- | --- | --- | --- |
| Medium | `skills/howells-boundaries/SKILL.md:10` | The skill is good when explicitly invoked, but repo-local agents do not automatically see commands and boundaries. | Context Files |
| Medium | `README.md:13` | README documents usage, but lacks a compact agent section with exact verification commands and expected outputs. | Discovery & AEO |
| Low | `package.json:4` | Package metadata has no repository, bugs, homepage, or keywords. | Discovery & AEO |

Suggested approach: add root `AGENTS.md`, enrich package metadata, and add a short "Agent usage" section to README.

Dependencies: none.

### Tests Cover Core Behavior But Not Consumer Reality

The current tests are fast and useful, but the published package path is not under test.

| Severity | File | Issue | Dimension |
| --- | --- | --- | --- |
| Medium | `test/cli.test.js:21` | CLI test covers local source execution but not packed install/bin resolution. | Testing |
| Medium | `test/init.test.js:9` | Init test covers writing config, but not `--dry-run` because it does not exist. | Testing |
| Low | `package.json:15` | No `prepack` or release verification script. | Testing |

Suggested approach: add a pack/install smoke test and a `prepack` script that runs tests plus skill validation.

Dependencies: optional; can be done before CLI JSON work.
